## Interpretation

A proposed guarantee is an externally meaningful behavioral, security, privacy, recovery, deployment, or repository-policy invariant identified by this audit. A filename, function name, test title, exact command spelling, fixed inventory count, or required source fragment is not a guarantee unless the repository explicitly depends on that declaration itself.

The “primary evidence” column identifies the evidence that should remain authoritative. The duplicate/meta column identifies checks that may be deleted only after the listed primary evidence is verified against a representative failing fixture.

### Fresh-initialization failure boundary

The owner [explicitly retired automatic same-path retry](https://github.com/smallwiselabs/swl-step-by-step/issues/92#issuecomment-4950073444) after a failed first-ever migration. Such a failure must remain closed. Empty-ledger state must never trigger automatic deletion or adoption, migration must not seed a user or admin account, and manual reset is permitted only for fully stopped state proven to have never initialized and to contain no user or application data. The database and all `-wal`, `-shm`, and `-journal` state must be discarded together.

The committed behavior suite owns successful fresh/repeat initialization and readiness. A controlled run against the copied actual maintenance executable, pinned Drizzle `0.45.2`, packaged migrations, and temporary SQLite characterized the current first-failure behavior: application changes rolled back, an empty ledger table remained, and same-path retry failed closed. Under #92's explicit deletion-only scope, the empty-ledger and no-seeded-account review/operator invariants do not gain a new durable regression test. That limitation is recorded rather than overstating the retained evidence.

## Guarantees needing owner decisions

### Coverage bookkeeping

The owner approved aggregate maximum-uncovered ceilings and explicit broad source inclusion as the coverage guarantee. CI-S03/#72 retires the exact production/test/result inventories, per-file debt/classification tuples, custom normalized report, retained artifact, wrapper deadline/interruption guarantee, and repeated whole-suite mutation runs. Coverage improvements do not automatically create a lower ceiling: lowering a reviewed native threshold remains an explicit reviewable update, and `autoUpdate` stays disabled in CI.

Recognized coverage-ignore hints remain prohibited through a narrow policy using the pinned converter's exact tool prefixes and directive terms. The policy scans raw source because `start`/`stop` hints do, and it also retains the security-relevant source-root symlink boundary. The small terminal-state reporter retains skipped/todo/expected-failure/missing/non-passing rejection. Aggregate headroom can offset a per-file regression; that accepted limitation is why behavioral and security tests remain primary.

### Documentation links

The owner confirmed that repository Markdown is development-only and does not require automatic content or link monitoring. `DOC-01` is retired in full: ordinary local files/headings and the former GitHub-line, Roam, raw-HTML, tracked/untracked, symlink, and traversal edge policies may all merge without CI validation. Because the old loader rejected every tracked symlink before it filtered Markdown, #74 also explicitly retires that incidental repository-wide prohibition; focused coverage, maintenance, container, and other security-sensitive symlink defenses remain. CI-S05/#74 adds no replacement.

### Actual-runner interruption

The owner explicitly retired `INT-01D` for CI-S02B/#70. The runtime and integration implementations retain their ordinary cleanup paths and best-effort catchable-signal handlers, while generic coordinator tests continue to exercise the shared handler mechanics. Those helper tests do not prove that interrupting the actual built or integration runner removes every child and temporary file. No replacement fixture is required. The accepted risk is bounded to interrupted CI/local runs leaving temporary state or a child process for operating-system or manual cleanup; ordinary success and injected-failure cleanup, output redaction, loopback isolation, and deployment no-write evidence remain required.

### CSS/PWA

They were source bookkeeping or weaker proxies for rendered behavior and require no one-for-one replacement. ### Browser result completion

Playwright `1.61.1` exposes the complete discovered suite and configured projects to `onBegin`, each test's project suite and logical source/title identity, terminal test runs to `onTestEnd`, and `onEnd` status override. CI-S02C1/#90 keeps those supported extension points but removes the fixed six-result inventory. The reporter now requires every configured project to discover the same nonempty logical test set, then requires exactly one known terminal result per unique discovered ID, with `passed` result and expected status, `expected` outcome, and a passed full run. Focused cases reject an empty or partially filtered project, zero/duplicate discovery, suite skips, expected failures, missing/duplicate/unknown results, interruption, flaky outcomes, non-passed full results, and reporter callback failure. A focused test separately imports and evaluates the actual Playwright configuration to require the reporter, `forbidOnly`, and the two approved Chromium viewports.

No test-file, journey, result, or Axe-invocation count remains a guarantee. A newly added or removed browser scenario must be reviewed for product coverage; once Playwright discovers it, every configured project must discover the same logical scenario set and completion integrity is dynamic.

### Container evidence boundary

Docker's official [build-context documentation](https://docs.docker.com/build/concepts/context/) states that `.dockerignore` removes matched paths before the context is sent to the builder, supports `**`, and resolves negations by the last matching rule. CI-S02C2/#91 therefore removes the parsed rule-presence policy and instead generates representative environment/database/journal/key/certificate/backup/data canaries beneath the root and an allowlisted tree, then inspects the effective build-stage filesystem. Exact production allowlists and Dockerfile/driver implementation mirrors are removed.

Docker documents that the default runtime identity is root unless [`USER` or `--user`](https://docs.docker.com/engine/containers/run/#user) selects another identity, that [named volumes persist independently of container lifecycle](https://docs.docker.com/engine/storage/volumes/), and that [`HEALTHCHECK`](https://docs.docker.com/reference/dockerfile/#healthcheck) uses exit status and consecutive failures to transition between `starting`, `healthy`, and `unhealthy`. The actual image configuration, runtime UID/GID, two-generation named-volume, and daemon health observations are consequently primary. The focused health test executes the shipped probe for exact-ready, extra-field, `503`, missing-token, and unresponsive cases; it does not search for the probe's implementation expressions.

No exact Dockerfile instruction, runner helper, command-array spelling, timeout constant, scenario count, local-object function name, or test title remains a guarantee. The unchanged maintenance runner still requests Docker's documented [`none` network driver](https://docs.docker.com/engine/network/drivers/none/), but #91 adds no new source assertion or generic runtime inspection solely to protect that argument. That implementation detail is review-owned unless a later bounded behavioral owner is separately approved.
