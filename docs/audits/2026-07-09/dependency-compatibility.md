R-005A implementation update (2026-07-09): the historical Better Auth row above described the audit input. [GHSA-86j7-9j95-vpqj](https://github.com/advisories/GHSA-86j7-9j95-vpqj) identifies `1.6.13` as the first fixed release; this repair pins the current stable Better Auth `1.6.23` and directly declares the dedicated `@better-auth/drizzle-adapter` `1.6.23` package. The application keeps `betterAuth` from `better-auth` and moves only `drizzleAdapter` to the dedicated import. A pre-update reproducer against `1.6.11` showed both OIDC and MCP registration schemas accepting a `javascript:` redirect; the seven-test post-update fixture proves both schemas reject `javascript:`, `data:`, and `vbscript:` values and accept HTTPS plus localhost/127.0.0.1 controls. It also checks exact installed versions, the source import, and disposable SQLite/Drizzle initialization. The factories are test-only: no plugin is enabled, and the built server keeps `POST /api/auth/oauth2/register` at `404` while seven bounded auth journey checks run solely against temporary state. Version-matched `auth@1.6.11` and `auth@1.6.23` generation produced byte-identical 3,597-byte schema files (SHA-256 `2f2cee42bc70d7926cd36bf49cdcb4926a67d2e3a81746c7bd431bad3156a7b7`), so no schema or migration is committed. The CLI joins `--output` to its working directory even when the value begins with `/`; the verified run used a relative traversal to place its artifact in system `/tmp`, and the earlier worktree-local `tmp/` artifact was removed. The remaining esbuild `0.18.20` path is exactly `drizzle-kit` → `@esbuild-kit/esm-loader` → `@esbuild-kit/core-utils` and is transferred to [R-005D/#45](https://github.com/Josephdhng/swl-step-by-step/issues/45), not overridden. The post-update graph has 1,276 packages, four reviewed tuples in three advisory groups, and three exception records. Magic link, social login, workspaces, password-policy changes, plugin enablement, Drizzle upgrades, and the separate esbuild patch are non-goals.

Declared dependency policy is also inconsistent: `drizzle-zod`, `stylelint`, and `stylelint-config-standard-vue` use caret ranges even though the target contract requires exact application/dev versions. R-004 closes this without mixing in unrelated upgrades.

## Compatibility PR rule

Each dependency PR should state:

- why the update is required (advisory, official API change, or maintained patch);
- exact old/new versions and lockfile scope;
- any generated schema/migration impact;
- official documentation used;
- targeted tests for the affected runtime/provider;
- full `verify`, built-server smoke, and Docker result;
- rollback method and residual advisories.

Do not combine Nuxt, Better Auth/workspace, Drizzle v1, Stripe SDK, AI Gateway, Sentry, Reka, and PWA migrations in one modernization PR.
